# 수동 테스트 체크리스트 — 네이버 아파트 매물 조회 웹

> 브라우저에서 직접 클릭하며 확인하는 QA 체크리스트
> 테스트 환경: http://localhost:8090 (프론트, 본 PC 3000=sangse / 3100=legal 점유, naver 는 8090 — 세션 114 박제) + http://localhost:8002 (백엔드)

---

## 1. 홈 페이지: http://localhost:8090

### 정상 흐름
- [ ] 페이지 접속 시 상단 헤더에 "네이버 아파트 매물 조회" 표시됨 → 기대: 헤더 렌더링 정상
- [ ] DB 통계 영역에 "단지 N개, 매물 N개" 숫자 표시됨 → 기대: 0 이상의 정수
- [ ] 검색 입력창에 "래미안" 입력 후 Enter 키 누름 → 기대: /search?q=래미안 으로 이동
- [ ] 시도 드롭다운에서 "서울특별시" 선택 → 기대: 시군구 드롭다운에 "강남구, 서초구..." 등 표시
- [ ] 시군구에서 "강남구" 선택 → 기대: 동 드롭다운에 "역삼동, 삼성동..." 등 표시
- [ ] 지역 선택 후 검색 버튼 클릭 → 기대: /search?sido=서울특별시&sigungu=강남구 로 이동

### 예외 상황
- [ ] 빈 검색어 상태에서 Enter → 기대: 검색 실행 안 됨 또는 안내 메시지
- [ ] 백엔드 서버 종료 후 페이지 새로고침 → 기대: 에러 메시지 표시, 페이지 자체는 렌더링

### 모바일 (375px)
- [ ] DevTools에서 375x812 설정 후 홈 페이지 확인 → 기대: 검색/지역 영역 세로 정렬, 가로 스크롤 없음

---

## 2. 검색 결과: /search?q=래미안

### 정상 흐름
- [ ] 검색 결과 테이블에 단지명, 주소, 세대수, 매물수 컬럼 표시 → 기대: 4개 이상 컬럼
- [ ] 로딩 중 스피너 또는 스켈레톤 표시됨 → 기대: 빈 화면이 아님
- [ ] 단지명 "래미안..." 행 클릭 → 기대: /complex/[번호] 페이지로 이동

### 예외 상황
- [ ] "zzz999" 입력 후 검색 → 기대: "검색 결과가 없습니다" 메시지
- [ ] URL에 q= 없이 /search 직접 접근 → 기대: 빈 상태 또는 홈으로 리다이렉트

---

## 3. 단지 상세: /complex/[no]

### 정상 흐름
- [ ] 페이지 접속 시 자동으로 크롤링 시작 → 기대: 진행 표시 후 매물 테이블 로드 (최대 120초)
- [ ] 매물 테이블에 거래유형, 동, 층, 가격, 면적, 방향 컬럼 표시
- [ ] "가격" 컬럼 헤더 클릭 → 기대: 가격 오름차순 정렬, 화살표 표시
- [ ] "가격" 컬럼 헤더 다시 클릭 → 기대: 가격 내림차순 정렬
- [ ] 필터 영역에서 거래유형 "매매" 체크박스만 선택 → 기대: 매매 매물만 표시
- [ ] 가격 필터에 최소 30000, 최대 50000 입력 → 기대: 3억~5억 매물만 표시 (300ms 후)
- [ ] "초기화" 버튼 클릭 → 기대: 모든 필터 해제, 전체 매물 표시
- [ ] 매물 행 클릭 → 기대: 매물 상세 모달 (사진, 공인중개사 정보, 주소)
- [ ] 모달에서 ESC 키 누름 → 기대: 모달 닫힘
- [ ] "엑셀 내보내기" 버튼 클릭 → 기대: .xlsx 파일 다운로드
- [ ] 체크박스로 3건 선택 후 "선택 3건 내보내기" 클릭 → 기대: 선택된 3건만 .xlsx로 내보내기

### 예외 상황
- [ ] /complex/99999999 직접 접근 → 기대: 404 에러 UI + "검색 페이지로 이동" 안내
- [ ] 크롤링 중 뒤로가기 후 다시 접속 → 기대: 에러 없이 정상 동작

---

## 4. 로그인: /login

### 정상 흐름
- [ ] 이메일 입력: test@example.com, 비밀번호 입력: Test1234!@ → "로그인" 클릭 → 기대: 홈으로 리다이렉트, 헤더에 이메일 표시
- [ ] 로그인 상태에서 /login 재접속 → 기대: 홈으로 리다이렉트

### 예외 상황
- [ ] 잘못된 비밀번호 "wrong123" 입력 후 로그인 → 기대: "이메일 또는 비밀번호가 올바르지 않습니다"
- [ ] 빈 이메일로 로그인 시도 → 기대: 브라우저 기본 유효성 검사 (required)
- [ ] 5회 연속 잘못된 비밀번호 입력 → 기대: "요청 한도 초과. N초 후 다시 시도" 메시지

---

## 5. 회원가입: /signup

### 정상 흐름
- [ ] 이메일: new@example.com, 비밀번호: NewPass1!, 확인: NewPass1! 입력 후 "가입" → 기대: 성공 메시지
- [ ] 비밀번호 입력 중 강도 표시기 업데이트됨 → 기대: 조건별 (대문자, 소문자, 숫자, 특수문자, 8자+) 체크

### 예외 상황
- [ ] 비밀번호: Pass1! / 확인: Pass2! (불일치) → 기대: "비밀번호가 일치하지 않습니다"
- [ ] 약한 비밀번호 "1234" 입력 → 기대: 강도 표시기 빨간색, 제출 불가

---

## 6. 비밀번호 찾기: /forgot-password

### 정상 흐름
- [ ] 이메일 입력 후 "비밀번호 재설정" 클릭 → 기대: "재설정 메일을 발송했습니다" 메시지

### 예외 상황
- [ ] 빈 이메일 제출 → 기대: 유효성 검사 에러
- [ ] 연속 5회 이상 제출 → 기대: 429 "잠시 후 다시 시도" 피드백

---

## 7. 관리자: /admin (관리자 계정으로 로그인)

### 정상 흐름
- [ ] 관리자 로그인 후 /admin 접속 → 기대: 통계 카드 (단지수, 매물수, 사용자수 등)
- [ ] /admin/users 접속 → 기대: 사용자 목록 테이블
- [ ] 사용자 역할을 "expert"로 변경 → 기대: 성공 피드백
- [ ] /admin/crawl 접속 → 기대: 크롤 작업 테이블
- [ ] /admin/logs 접속 → 기대: 감사 로그 목록
- [ ] /admin/settings 접속 → 기대: 설정 편집 화면

### 예외 상황
- [ ] 일반 사용자로 /admin 접근 → 기대: /login 또는 / 로 리다이렉트
- [ ] 비로그인 상태로 /admin 접근 → 기대: /login 리다이렉트

---

## 8. 단지 비교: /compare?ids=no1,no2

### 정상 흐름
- [ ] 2개 이상 단지 비교 시 비교 테이블 24행 표시 (평당가 포함) → 기대: 우위 항목에 ★ 표시
- [ ] 레이더 차트 9축 (세대수, 주차, 전세가율, 거래, 매물수, 신축도, 시세, 최고층, 평당가)
- [ ] 현재 평균가 바 차트: 매매/전세/월세 각 ★ 최고값 표시
- [ ] "인쇄" 버튼 클릭 → 기대: 모든 아코디언 펼쳐진 상태로 인쇄 미리보기, 헤더/버튼 숨김
- [ ] "엑셀" 버튼 클릭 → 기대: 단지비교_YYYY-MM-DD.xlsx 다운로드, 24행 × N열
- [ ] 엑셀 "생성 중..." 로딩 표시 → 기대: 완료 후 자동 다운로드

### 예외 상황
- [ ] 1개 단지만 선택 시 → 기대: "2개 이상 선택" 안내
- [ ] 평당가 로딩 중 → 기대: "불러오는 중..." 표시

---

## 9. Header (공통)

- [ ] 비로그인 상태: 헤더에 "로그인" 링크 표시 → 기대: 클릭 시 /login 이동
- [ ] 로그인 상태: 헤더에 이메일 + "로그아웃" 버튼 표시
- [ ] 관리자 로그인: 헤더에 "관리자" 링크 추가 표시
- [ ] "로그아웃" 클릭 → 기대: 세션 종료, "로그인" 링크로 전환

---

## 10. 에러/로딩 상태

- [ ] 존재하지 않는 URL (예: /asdf) 접근 → 기대: 404 페이지 + 홈으로 이동 링크
- [ ] 에러 바운더리: 컴포넌트 오류 시 전체 페이지 크래시 없이 에러 UI 표시
