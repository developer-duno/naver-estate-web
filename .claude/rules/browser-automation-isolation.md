# 브라우저 자동화 실계정 분리 확인 (라이브 조사 전 의무 — 세션 351 실토큰 노출 사고)

브라우저 자동화(chrome-devtools MCP·playwright MCP 등)로 라이브 사이트를 조사·재현하기
전, 그 자동화 브라우저가 **사용자의 실제 로그인 세션과 분리돼 있는지** 먼저 확인한다.
분리 확인 없이 진행하면 실계정 쿠키·JWT 토큰이 조사 출력(대화 전사·로그)에 그대로
박제될 수 있다 — **전사에 남은 토큰은 회수 불가**, 로그아웃→재로그인(토큰 회전)만이 답.

## 함정 — "자체 프로필이니까 안전" 은 절반만 맞다

chrome-devtools MCP 는 기본값으로 자체 Chrome 인스턴스 + 전용 프로필을 띄우지만, 그
프로필은 **영속(persistent)** 이다 — `%HOMEPATH%/.cache/chrome-devtools-mcp/chrome-profile*`
에 저장되고 "run 간 삭제되지 않으며 모든 인스턴스가 공유"(공식 README, 2026-08-09 확인).
즉 **과거 어느 세션에서든 한 번 로그인했으면 지금도 로그인 상태**다. `--browserUrl` /
`--wsEndpoint` 로 사용자가 쓰는 실제 크롬에 붙는 모드면 실프로필 그 자체를 공유한다.
일회용이 필요하면 `--isolated`(종료 시 자동 삭제 임시 프로필).

## 시작 전 체크 (예외 0)

1. **자동화 브라우저로 대상 사이트 접속 → 로그인 상태부터 확인.**
   - 비로그인 = 분리 확인 완료, 진행.
   - 로그인돼 있음 = 실계정 세션 보유 중(레드 플래그). 진행 중단하고 2번으로.
2. **로그인 상태로 발견되면**: 사용자에게 먼저 보고. 격리 프로필(`--isolated` 등)로
   재시작하거나, 실계정 세션이 조사에 꼭 필요하면 **사전 고지 + 토큰·쿠키 원문 dump
   금지**(document.cookie·localStorage·Authorization 헤더 값을 출력에 찍지 않는다 —
   존재 여부·길이·앞 4자리 마스킹까지만) 조건으로만 진행.
3. **E2E 테스트 계정과 실계정을 혼용하지 않는다** — 라이브 조사에 로그인이 필요하면
   테스트 계정 우선.

## 토큰이 이미 노출됐다면

(1) 인정(변명 0) (2) 어느 계정·어느 세션 토큰인지 명시 (3) 해당 계정 로그아웃→재로그인
(리프레시 토큰 회전) 안내 (4) 본 룰에 사례 추가.

## 사건 (왜 이 룰?)

2026-08-07 세션 351 — 멀티탭 로그인 튕김 버그(auth-js#213)를 chrome-devtools MCP 로
라이브 반복 재현하던 중, 자동화 브라우저가 사장님의 실제 로그인 세션 쿠키를 쥐고 있어
**실 JWT 토큰 값이 조사 결과 텍스트에 그대로 노출**. 사장님이 "본인 계정이라 괜찮다"며
진행을 승인했으나, 재발방지 P0 로 박제 → 세션 353 본 룰 신설.
