손님이 "어제 보여주셨던 그 단지 다시 볼 수 있을까요?" 물어보면 보통 단지명을 다시 받아 검색창에
입력해야 합니다. 손님이 동·아파트명을 정확히 기억 못하면 5분이 사라지죠.
이 사이트는 **단지 검색·미분양 검색·미분양 비교 결과를 localStorage 4 키에 자동 저장**해서
어제 상담 자료를 30초 만에 복원할 수 있도록 설계했습니다.

저장 한도는 단지 검색 10개 + 미분양 검색 10개 + 비교 자동 10개 + 비교 북마크 수동 20개 = **총 50개**.

## 검색 히스토리란 무엇인가

검색창에 키워드를 넣거나 지역을 골라서 검색하면, 브라우저의 localStorage 에 자동으로 기록됩니다.
이름은 `search_history` 한 키이고, **최대 10개**까지 저장됩니다. 11번째 검색이 들어오면
가장 오래된 1개가 자동으로 빠집니다.

저장 항목은 두 종류로 구분돼요. **키워드 검색** (예: "은마아파트") 과 **지역 검색**
(예: "서울 강남구 대치동") 입니다. 둘은 같은 10개 한도를 나눠 씁니다.

같은 검색을 반복해도 목록이 막히지 않게 **중복 제거**가 들어 있어요. 동일 키워드는 기존 기록을
지우고 새 시각으로 다시 맨 위로 올라옵니다. 지역은 시·시군구·동 3개가 모두 일치할 때만 동일하다고
판단합니다 (예: "강남구 대치동" 과 "강남구 신사동" 은 별개로 저장).

같은 1초 안에 두 번 검색해도 시각이 같지 않도록 내부에서 **시간 충돌 방지**가 들어 있습니다.
ms 가 같으면 자동으로 +1 해서 항목 순서가 뒤바뀌지 않습니다. 서버 사이드 렌더링 (SSR) 환경에서는
localStorage 가 존재하지 않으므로, 브라우저에 로드된 다음에야 기록이 보입니다.

## 단지 검색 vs 미분양 검색 — 별도 보관

같은 손님이라도 매수 상담과 분양 상담은 보통 다른 자료를 봅니다. 단지 검색과 미분양 검색을
**같은 목록에 섞으면** 어제 매수 손님 자료를 분양 상담 자리에서 우연히 보여드리는 사고가 납니다.

그래서 사이트는 두 키를 분리했습니다.

- **`search_history`** — `/` 메인 페이지와 `/search` 검색 페이지에서 사용. 단지·지역 검색 자료.
- **`mb_search_history`** — `/mibunyang` 미분양 페이지에서 사용. 지역 + 구 + 키워드 자료.

미분양 검색은 region 이 필수이고 gu·keyword 는 선택입니다. 비어 있는 값은 자동으로 제거돼서
보관 자료가 깔끔하게 유지됩니다. 두 키 모두 10개 한도라서 손님 약 5명분 (왕복 검색 2회 가정)
자료가 자연스럽게 사라지지 않고 남습니다.

## 손님 재방문 30초 응대 워크플로

어제 손님이 본 "○○동 ○○아파트" 를 다시 보여드리는 흐름은 이렇습니다.

1. **검색창 아래 "최근 검색" 칩 확인** — 사이트 진입 직후 검색창 바로 아래 칩이 자동으로 뜹니다.
   가장 최신 검색이 맨 왼쪽이에요.
2. **칩 1번 클릭** — `/search?q=○○아파트` URL 이 자동으로 만들어지면서 어제 본 검색 결과가
   그대로 떠요. 동·아파트명을 다시 받아 입력할 필요가 없습니다.
3. **시세 추이 차트 확인** — 단지 클릭 → 6개월·1년·2년 시세 추이 차트로 어제 이후 시세 변동을
   1초 안에 봅니다.
4. **+ 비교 추가** — 매수 후보 단지 3~4개를 [/compare](/compare) 로 보내 24행 자료를
   5분에 만듭니다.

칩에는 단건 **x 삭제** 와 **전체 삭제** 두 버튼이 있어요. 손님 자료가 너무 오래 남는 게 불편하면
"전체 삭제" 로 한 번에 정리하고 다음 손님을 받을 수 있습니다.

## 검색 히스토리의 한계

좋은 도구도 한계가 있어요. 손님께 자료를 약속하기 전에 알아두면 좋은 점 5가지입니다.

- **10개 한도** — 11번째 검색이 들어오면 가장 오래된 1개가 빠집니다. 손님 5명 이상 동시에
  돌리시면 일부 자료가 사라질 수 있어요.
- **브라우저별 독립** — localStorage 는 도메인·브라우저 단위 저장소입니다. 사무실 크롬에서
  저장한 자료가 집 사파리에서는 안 보입니다. 같은 PC 라도 크롬·엣지·웨일 사이에 자료가 공유되지
  않아요.
- **시크릿 모드 비어있음** — Private Browsing 모드는 localStorage 가 빈 상태로 시작합니다.
  손님 PC 빌려 잠깐 검색하실 때 자료가 안 쌓이는 게 정상이에요.
- **SSR hydration 안전 박제** — 페이지 첫 로드 시점에는 칩이 잠깐 안 보일 수 있어요. 브라우저
  자바스크립트가 로드된 다음에 자동으로 채워집니다 (`useEffect` 안에서 읽기).
- **B2B 구독 서버 동기화 로드맵** — 현재는 PC 단위 저장이지만, 향후 [공인중개사 인증](
  /blog/agent-verification-guide) 자료가 서버에 동기화되는 시점에 검색 히스토리도 함께 동기화될
  예정입니다. 그때부터는 사무실·집·태블릿 모두 같은 자료가 보입니다.

## 자매 자산: 비교 히스토리 + 북마크

미분양 페이지에는 검색 히스토리 외에 **2종의 자매 자산**이 더 있습니다. 잘 모르고 지나치기 쉬워서
이 글에서 함께 박제해 둡니다.

**`mb_compare_history` (자동, 10개)** — 미분양 비교 페이지 (`/mibunyang/compare`) 에 들어가는
순간 어떤 단지 조합을 봤는지 자동으로 저장됩니다. 손님이 며칠 뒤 와도 그때 본 3단지·5단지 조합을
원클릭으로 복원해요. 단지 ids 정렬 + 쉼표 join 으로 **동일 조합 중복 제거**가 들어 있어서, 같은
조합을 여러 번 봐도 한 줄로 묶입니다.

**`mb_compare_bookmarks` (수동, 20개)** — 자동 히스토리는 10개 한도라 손님 자료가 사라질 수
있어요. 정말 자주 보는 비교 조합은 **별표(★) 버튼으로 수동 북마크**하면 별도 키에 20개까지
저장됩니다. 라벨도 직접 지정 가능 (비워두면 단지 이름을 " vs " 로 연결한 자동 라벨). 같은 조합을
다시 북마크하면 새 항목이 안 생기고 **라벨만 업데이트**됩니다.

이 두 자산은 **미분양 페이지 한정**입니다. 단지 검색에는 비교 히스토리·북마크가 없어요
(자매글: [/compare 24행 비교 워크플로](/blog/compare-workflow) 의 4단지 비교는 URL 자체가
공유 자료 역할).

## 손님 응대 화법 예시

칩과 북마크만으로는 손님이 어떻게 활용되는지 막막할 수 있어요. 한 줄 화법 3가지를 추천드립니다.

> "지난번에 보셨던 ○○아파트, 검색 히스토리에서 바로 찾아 드리겠습니다. 어제 이후 시세 변동도
> 같이 보시죠."

> "어제 보신 3단지 미분양 비교 그대로 다시 띄워 드릴게요. 자주 보실 조합이면 ★ 북마크로 저장해
> 두면 다음에 한 번 클릭으로 떠요."

> "이 자료는 사무실 PC 에 저장돼 있어요. 다른 기기로 보시려면 같은 단지명만 한 번 더 입력해
> 주시면 됩니다. 곧 인증 가입자분들은 PC·태블릿 자료가 자동 동기화되도록 준비 중입니다."
