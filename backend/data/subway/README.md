# 전국 도시철도 역사 정보

- 출처: 국가철도공단 레일포털 "전체_도시철도역사정보" — https://data.kric.go.kr/rips/M_01_01/detail.do?id=32
- 원본 파일: `전체_도시철도역사정보_20260630.xlsx` (시트 "표준데이터 역사")
- 다운로드일: 2026-08-14 / 데이터 기준일: 2026-06-30 (파일명 기준)
- 갱신 주기: 연 1회. 새 파일이 나오면 같은 규칙으로 CSV 를 만들고 파일명의 날짜를 바꾼다.
- 좌표계: WGS84 (위도/경도). 전국 1,099행, 좌표 결측 0.

## 정규화 규칙 (원본 15컬럼 → CSV 8컬럼)

영문/한자 역사명·주소·전화번호·환승 컬럼은 버린다 — 환승 표시는 조회 시 역명 그룹핑으로
해결하므로 저장할 이유가 없다. 그 외 정규화는 `scripts/import_subway_stations.py` 의
`parse_row()` 가 담당하며, 재적재 시에도 같은 함수를 통과한다:

- 모든 텍스트 컬럼은 앞뒤 공백 제거 + 연속 공백 1칸으로 축약
  (원본에 `수도권  도시철도 9호선` 처럼 공백이 둘 박힌 값이 있다).
- `data_date` 는 `YYYY-MM-DD` / `YYYYMMDD` 를 모두 받아 ISO 로 통일하고, 파싱 불가한 값
  (`1900-01-00`, 빈칸 등 13행)은 빈칸으로 둔다 → DB 에는 NULL. 이 컬럼은 원본의 **행별
  게시일**이라 2022~2026 로 흩어져 있다. 데이터셋 전체의 기준일(2026-06-30)은 이 컬럼이
  아니라 파일명과 이 문서가 진실의 원천이다.

⚠ 원본이 같은 노선을 `서울 도시철도 9호선` 과 `수도권 도시철도 9호선` 두 이름으로
싣는다(각각 다른 구간의 역들). 표기 통일은 제품 결정이라 임의로 바꾸지 않고 원본 표기를
그대로 저장한다 — 화면에 노선명을 묶어 보여줘야 하면 그때 별도 매핑을 둔다.

## 재적재

```bash
cd backend
python -m scripts.import_subway_stations                       # data/subway/ 최신 CSV 자동 선택
python -m scripts.import_subway_stations data/subway/xxx.csv   # 파일 명시
```

전량 DELETE 후 INSERT 한다(연 1회 갱신이라 증분 upsert 불필요). 사전에 마이그레이션
`db/migrations/V047__subway_stations.sql` 이 prod 에 적용돼 있어야 한다.
